# Migrating from 0.4 to 0.5

RouchDB 0.5 is a CouchDB-fidelity release: behavior was checked against CouchDB 3.5.1 and changed wherever RouchDB disagreed. Most programs only need the first few sections below; the rest lists behavior changes you may rely on without knowing it. The full list is in the [changelog](https://github.com/rubylab-app/rouchdb/blob/main/CHANGELOG.md).

---

## Update the dependency

```toml
[dependencies]
rouchdb = "0.5"
```

HTTPS now uses rustls with bundled Mozilla roots by default. If your CouchDB certificate is signed by a private CA installed in the OS trust store, pick a TLS feature that reads the OS store:

```toml
[dependencies]
rouchdb = { version = "0.5", default-features = false, features = ["rustls-tls-native-roots"] }
# or features = ["native-tls"] for the platform TLS stack (the only option in 0.4)
```

The minimum supported Rust version is 1.88.

---

## Single-document writes return errors

`put`, `update`, `remove`, `post` and `put_design` used to return `Ok` with `ok: false` when the write failed. They now return `Err`, like every other failing call. `bulk_docs` still returns one `DocResult` per document.

```rust
// 0.4
let res = db.update("doc1", &rev, json!({"n": 2})).await?;
if !res.ok {
    // stale revision
}

// 0.5
match db.update("doc1", &rev, json!({"n": 2})).await {
    Ok(res) => println!("new rev {}", res.rev.unwrap_or_default()),
    Err(RouchError::Conflict) => { /* stale revision: re-read and retry */ }
    Err(e) => return Err(e),
}
```

Related changes, identical on the memory, redb and HTTP adapters:

| Call | 0.4 | 0.5 |
|---|---|---|
| `update` of a document that does not exist | `ok: false` (`not_found`) | `Err(Conflict)` |
| `remove` of a missing or already deleted document | `ok: false` (over HTTP it could write a tombstone) | `Err(NotFound)` |
| `get` with a malformed `rev` (`"garbage"`) | `NotFound` (local), `BadRequest` (HTTP) | `Err(InvalidRev)` |
| `get` of a stemmed or compacted revision | `Ok` with a stale or empty body | `Err(NotFound)` |

## Option defaults equal `new()`

`BulkDocsOptions::default()` used to mean **replication mode** (`new_edits: false`) and `AllDocsOptions::default()` an **exclusive** `end_key`. Both now equal `new()`.

```rust
// 0.4: silently wrote in replication mode
db.bulk_docs(docs, BulkDocsOptions::default()).await?;
// 0.5: Default is a normal write; ask for replication explicitly
db.bulk_docs(docs, BulkDocsOptions::replication()).await?;

// 0.4: end_key excluded unless you used new()
AllDocsOptions { end_key: Some("m".into()), ..Default::default() }
// 0.5: end_key is inclusive, like CouchDB; opt out explicitly
AllDocsOptions { end_key: Some("m".into()), inclusive_end: false, ..Default::default() }
```

## `all_docs` rows

`AllDocsRow` has an optional `id` and `value` and a new `error`:

```rust
// 0.4
pub struct AllDocsRow { pub id: String, pub key: String, pub value: AllDocsRowValue, pub doc: Option<Value> }
// 0.5
pub struct AllDocsRow {
    pub id: Option<String>,             // None for an error row
    pub key: String,                    // always set; the id for document rows
    pub value: Option<AllDocsRowValue>, // None for an error row
    pub doc: Option<Value>,
    pub error: Option<String>,          // Some("not_found") for an unknown key
}
```

```rust
// 0.4
for row in &resp.rows {
    println!("{} {}", row.id, row.value.rev);
}
// 0.5: `key` is the document id of a document row; `rev()` its revision
for row in &resp.rows {
    println!("{} {}", row.key, row.rev().unwrap_or_default());
}
```

With `keys`, rows match the request one to one, as in CouchDB and PouchDB. Unknown ids are no longer skipped, and deleted documents get a row too:

```rust
let resp = db.all_docs(AllDocsOptions {
    keys: Some(vec!["a".into(), "nope".into()]),
    ..AllDocsOptions::new()
}).await?;
// 0.4: rows == [a]     (memory/redb skipped "nope", HTTP dropped CouchDB's row)
// 0.5: rows == [a, not_found]    rows[1] == AllDocsRow::not_found("nope")
for row in &resp.rows {
    if row.is_error() { /* no such document */ }
    else if row.is_deleted() { /* value.deleted == Some(true), no doc */ }
    else if let Some(doc) = &row.doc { /* include_docs */ }
}
```

`skip` and `limit` count error rows too.

## Design documents

`DesignDocument` is lossless: any design document CouchDB accepts reads and writes back unchanged.

```rust
// 0.4
pub struct DesignDocument {
    pub id: String, pub rev: Option<String>,
    pub views: HashMap<String, ViewDef>,
    pub filters: HashMap<String, String>, pub validate_doc_update: Option<String>,
    pub shows: HashMap<String, String>, pub lists: HashMap<String, String>,
    pub updates: HashMap<String, String>, pub language: Option<String>,
}
pub struct ViewDef { pub map: String, pub reduce: Option<String> }

// 0.5
pub struct DesignDocument {
    pub id: String, pub rev: Option<String>,
    pub views: HashMap<String, ViewDef>,     // JavaScript views (string `map`)
    pub other_views: Map<String, Value>,     // new: `lib`, Mango (`language: "query"`) views
    pub filters: HashMap<String, Value>,     // String -> Value (CouchDB accepts objects)
    pub validate_doc_update: Option<String>,
    pub shows: HashMap<String, Value>,
    pub lists: HashMap<String, Value>,
    pub updates: HashMap<String, Value>,
    pub language: Option<String>,
    pub extra: Map<String, Value>,           // new: options, autoupdate, rewrites, custom fields
}
pub struct ViewDef { pub map: String, pub reduce: Option<String>, pub extra: Map<String, Value> }
```

Both types implement `Default` and have builders:

```rust
// 0.4
let ddoc = DesignDocument {
    id: "_design/app".into(), rev: None,
    views: HashMap::from([("by_type".into(), ViewDef { map: MAP.into(), reduce: Some("_count".into()) })]),
    filters: HashMap::new(), validate_doc_update: None, shows: HashMap::new(),
    lists: HashMap::new(), updates: HashMap::new(), language: None,
};
// 0.5 (or a struct literal with ..Default::default())
let ddoc = DesignDocument::new("app")
    .with_view("by_type", ViewDef::new(MAP).with_reduce("_count"))
    .with_filter("users", "function(doc) { return doc.type === 'user'; }");
```

Filter, show, list and update functions are `serde_json::Value`s:

```rust
// 0.4
ddoc.filters.insert("f".into(), "function(doc) { ... }".to_string());
let src: &String = &ddoc.filters["f"];
// 0.5
ddoc.filters.insert("f".into(), "function(doc) { ... }".into());
let src: Option<&str> = ddoc.filters["f"].as_str();
```

**`put_design` writes exactly the struct it is given**, like a `PUT`. In 0.4 it copied members the struct could not hold (`views.lib`, Mango views, custom fields) from the revision it replaced. If you build a fresh `DesignDocument` with a `rev`, start from the stored one instead, or those members are removed:

```rust
// 0.4: members not in the struct were copied from the stored revision
db.put_design(DesignDocument { rev: Some(rev), views: my_views, ..my_other_fields }).await?;
// 0.5: start from the stored document
let mut ddoc = db.get_design("app").await?;
ddoc.views = my_views;
db.put_design(ddoc).await?;
```

## Writes are validated like CouchDB

Documents written with `put`, `post`, `update` or `bulk_docs` (normal mode) are rejected with `BadRequest` when they:

- are not JSON objects;
- contain `_`-prefixed members CouchDB does not know (`_foo`), or reserved `_` ids;
- have a wrongly typed `_id`, `_rev`, `_deleted` or `_attachments`, or an empty `_id`;
- are nested deeper than `MAX_NESTING_DEPTH` (1000) levels.

Read-only metadata that `get` adds (`_conflicts`, `_revs_info`, `_revisions`) is dropped on write, so writing back a document you read is safe.

In `bulk_docs` results, the local adapters now give an invalid document's bare reason (`"Bad special document member: _foo"`), like the HTTP adapter and CouchDB; 0.4 prefixed it with `bad request: `.

### Generated ids

Ids generated by `post`, by `bulk_docs` for documents without `_id` and by the server's `POST /{db}` are 32 lower-case hex digits, as in CouchDB (still random UUID v4 values):

```rust
// 0.4: "0b9e4c52-5d7a-4f7e-9c1b-3a2f6e8d9c10"
// 0.5: "0b9e4c525d7a4f7e9c1b3a2f6e8d9c10"
let id = db.post(json!({"n": 1})).await?.id;
```

Over HTTP a document without an id is sent without `_id`, so CouchDB generates it.

### Nesting

Documents nested up to `MAX_NESTING_DEPTH` (1000) levels are accepted on every path, including the server and the CLI (0.4 failed above serde_json's 128 levels). `HttpAdapter::bulk_docs` rejects a deeper document with a per-document `BadRequest` instead of sending it.

```rust
// 0.5: Err(BadRequest), as in CouchDB: `_meta` is not a known special member
db.put("doc1", json!({"_meta": {"source": "import"}})).await?;

// 0.5: keep application metadata in a normal member
db.put("doc1", json!({"meta": {"source": "import"}})).await?;
```

### `_local/` ids

A `_local/…` id now means a local document on every adapter, as in CouchDB: revisions are `0-1`, `0-2`, …, there is no conflict check, and the document is not listed by `all_docs`, not in the changes feed and not replicated. In 0.4 the memory and redb adapters stored it as a normal, replicated document.

```rust
db.put("_local/settings", json!({"theme": "dark"})).await?; // rev "0-1"
db.get("_local/settings").await?;                           // still readable
// but it no longer appears in all_docs() or changes(), and does not replicate
```

If you relied on `_local/` documents replicating, rename them.

### Attachments

- Deleting a document drops its attachments.
- An explicit `_attachments` map is exact: entries you omit are removed (stubs keep an attachment). An empty map still keeps the parent's attachments.
- Stubs are matched by name; the stored metadata wins over the stub's. A stub for a name that has no stored attachment fails with `missing_stub`.

`AttachmentMeta` gains `revpos`, `encoding` and `encoded_length`:

```rust
// 0.4
let meta = AttachmentMeta { content_type: "image/png".into(), digest: String::new(), length: bytes.len() as u64, stub: false, data: Some(bytes) };
// 0.5: inline attachment, digest and length computed
let meta = AttachmentMeta::new("image/png", bytes);
// or add ..Default::default() to existing struct literals
```

`revpos` is the generation of the revision that uploaded the data, set by the write as in CouchDB, and it is now included in stubs (`Document::to_json`, `get`, `bulk_get`) and replicated, so attachments pushed to CouchDB no longer arrive with `revpos: 0`. Attachments stored by 0.4 in redb read back with `revpos` 0. `AttachmentMeta::to_json(data)` builds the CouchDB `_attachments` member.

## Revision history

- Stemming (`revs_limit`, default 1000) now prunes every branch, and the bodies of stemmed revisions are gone. Configure it with `MemoryAdapter::with_rev_limit` or `RedbAdapter::with_rev_limit` (`0` = unlimited).
- Re-creating a deleted document continues its history (`3-…` after `2-…` was deleted) instead of starting at `1-…`.
- Revision ids are normalized to lower-case hex.
- `rouchdb_core::merge::latest_rev` was removed. Use `latest_leaf`, which the adapters already used:

```rust
// 0.4
let rev = rouchdb_core::merge::latest_rev(&tree, pos, &hash);
// 0.5
let rev = rouchdb_core::merge::latest_leaf(&tree, pos, &hash);
```

## Mango queries

Mango now follows CouchDB, which differs from PouchDB and from 0.4 in a few places. This applies to `find`, `changes` with a selector, and selector-filtered replication.

**Missing fields.** A document without the field only matches `{"$exists": false}`. `$ne`, `$nin`, `$not` and `$nor` no longer match it:

```rust
// docs: {"_id": "a", "status": "archived"}, {"_id": "b"}  (no status)
let opts = FindOptions { selector: json!({"status": {"$ne": "archived"}}), ..Default::default() };
// 0.4: ["b"]   0.5: []

// 0.5: say it explicitly to keep the 0.4 result
let opts = FindOptions {
    selector: json!({"$or": [
        {"status": {"$ne": "archived"}},
        {"status": {"$exists": false}}
    ]}),
    ..Default::default()
};
```

**Projection.** `fields` returns only the fields you ask for; `_id` is no longer added. Nested paths keep their structure:

```rust
let opts = FindOptions {
    selector: json!({"type": "user"}),
    fields: Some(vec!["_id".into(), "address.city".into()]), // add "_id" if you need it
    ..Default::default()
};
// 0.5 result: {"_id": "u1", "address": {"city": "Lima"}}
```

**Errors instead of empty results.** Invalid selectors, unknown operators, bad operator arguments (`{"$not": 5}`, `{"$elemMatch": 1}`), invalid regexes and invalid sort fields are `Err(BadRequest)` with CouchDB's messages. A `null` selector is an error too; use `json!({})` to match everything.

**Other changes:**

- Nested objects are paths: `{"a": {"b": 1}}` means `{"a.b": 1}`.
- `$in` / `$nin` compare against array elements; `$all` uses exact equality.
- `find` never returns design documents.
- A selector that is only an empty combinator (`{"$and": []}`) returns nothing.
- `{}` below the top level is an equality test with `{}`: `{"$and": [{}]}` matches nothing, `{"o": {"$and": [{}]}}` matches `o == {}`. Operators without a field inside `$and`/`$or`/`$nor` (`{"$and": [{"$gt": 1}]}`) apply to the whole document instead of being rejected.
- Descending sort ties come in reverse index order.
- A sorted `find` skips documents that lack a sort field.
- `$regex` accepts PCRE-style lookaround and backreferences.
- `SortField` only deserializes from `"field"` or `{"field": "asc" | "desc"}`.

On `Database::http`, `find`, `create_index`, `get_indexes`, `delete_index` and `explain` now run on the CouchDB server, so results (including string order) are CouchDB's own.

## Views

`ViewQueryOptions::new()` now enables `reduce`, like CouchDB. If you pass a reduce function but want map rows, say so:

```rust
// 0.4: map rows, because new() left reduce off
let opts = ViewQueryOptions::new();
// 0.5: new() reduces; ask for map rows explicitly
let opts = ViewQueryOptions { reduce: false, ..ViewQueryOptions::new() };
```

Also:

- `_sum` and `_stats` keep integers (`90`, not `90.0`); arrays are summed element-wise and objects per field.
- `_sum` over values it cannot add (strings, mixed types) no longer fails the query: the row's value is CouchDB's error object, so check for it if your map functions can emit such values. `_stats` over such values is still `Err(BadRequest)`.

  ```rust
  // 0.5: emit(doc.type, doc.name) with _sum
  // rows[0].value == {"error": "builtin_reduce_error", "reason": "The _sum function requires ...", "caused_by": "alice"}
  if row.value.get("error").is_some() { /* not summable */ }
  ```

- These queries are now `Err(BadRequest)`, as in CouchDB: a key range that cannot match (`start_key` after `end_key` without `descending`, or the reverse with it), several `keys` together with `key`/`start_key`/`end_key`, and `group`/`group_level` on a map-only view or with `reduce: false`.

  ```rust
  // 0.4: Ok with no rows.  0.5: Err(BadRequest("No rows can match your key range, ..."))
  let opts = ViewQueryOptions { start_key: Some(json!("z")), end_key: Some(json!("a")), ..ViewQueryOptions::new() };
  // 0.5: say descending if you meant it
  let opts = ViewQueryOptions { start_key: Some(json!("z")), end_key: Some(json!("a")), descending: true, ..ViewQueryOptions::new() };
  ```

- `start_key`/`end_key` are honored next to `key` (an explicit bound replaces the one `key` implies), and `group` + `keys` keeps the keys' order when `descending`.
- Custom reduce functions receive `[key, doc_id]` pairs as keys, and `rereduce` is always `false`.
- Several `keys` with a reduce require `group: true` (and no `group_level`); `include_docs` with a reduce is an error.
- `total_rows` counts the whole view and `offset` is the position of the first returned row.
- Design documents are not passed to map functions.

### Collation

`-0.0` equals `0`, large integers and floats compare exactly, and strings compare by UTF-16 code units (PouchDB's order; only characters above U+FFFF move). `to_indexable_string` has a new format: rebuild anything you stored with it.

## Partitions

`Partition::all_docs` lists every id of the partition (0.4 missed ids sorting after `p:\u{10FFFF}`) and applies `inclusive_end` only to the end key you pass, never to the partition's own bound. `Partition::find` validates your selector as a whole selector first, and `{}` means every document of the partition.

## Plugins

`before_write` now also runs for `put_attachment` and `remove_attachment`, with the revision the attachment write creates. As for replicated documents it can only accept or reject: a rejection is returned and nothing is written, modifications are ignored, and dropping the document is `Forbidden`. If a plugin rejects documents by shape, check that it accepts attachment-only revisions of documents it accepted before.

## Replication and the HTTP adapter

**The remote database is created on first use**, as PouchDB does. To keep failing with `NotFound` when it is missing:

```rust
use std::sync::Arc;
use rouchdb::{Database, HttpAdapter, HttpAdapterOptions};

// 0.4
let db = Database::http("http://admin:password@localhost:5984/mydb");

// 0.5: same call creates `mydb` if needed; opt out with skip_setup
let adapter = HttpAdapter::with_options(
    "http://admin:password@localhost:5984/mydb",
    HttpAdapterOptions { skip_setup: true, ..Default::default() },
);
let db = Database::from_adapter(Arc::new(adapter));
```

`HttpAdapterOptions` also sets the timeouts (30 s to connect, 60 s of inactivity by default).

**One rescan after upgrading.** Replications with an HTTP peer get a new replication id (it now includes the server uuid), so the first run re-reads the changes feed from the start. `revs_diff` means no document is transferred again. Local-to-local replications keep their checkpoints.

**Other changes:**

- Documents rejected by a validation function (`forbidden` / `unauthorized`) are listed in `errors` and `ok` is `false`, but the replication moves past them instead of stopping forever.
- `ReplicationFilter::Custom` closures no longer use checkpoints: every run starts from `since`.
- For replicated documents, `before_write` plugins only accept or reject (their modifications are ignored), like CouchDB's `validate_doc_update`.
- HTTP errors are mapped from the status and CouchDB's `{error, reason}`: 400/413/415 → `BadRequest`, 412 `file_exists` → `DatabaseExists`, 401 → `Unauthorized`.

### Live feeds react immediately

Live changes feeds (`live_changes`, `live_changes_events`, `LiveChangesStream`) and `replicate_live` from a memory or redb database are woken by the adapter on each commit instead of polling. `poll_interval` now only applies to HTTP sources and to retry delays, and live replication emits `Paused` as soon as it is caught up (0.4 needed one more empty poll). Tests that counted polls or slept for `poll_interval` may need adjusting. `rouchdb_changes::ChangeNotification` is now an alias of `rouchdb_core::adapter::ChangeNotice` (same fields).

### `destroy`

After `destroy()` the handle stays usable and behaves as a new, empty database on every adapter (documents, local documents, attachments, security and Mango indexes are gone). The HTTP adapter re-creates the remote database on its next use, and destroying a database that no longer exists is `Ok`.

## Custom adapters

- `Adapter::put_security`'s default now returns `Err(BadRequest)` instead of silently succeeding. Implement it if your adapter stores security documents.
- New default method `Adapter::id()` (the database name). Override it if two instances of your adapter can share a name but not their data, so replications do not share checkpoints.
- `destroy` must leave the adapter usable as an empty database.
- New default method `Adapter::subscribe()` returning `None`: existing adapters compile unchanged and keep being polled. To wake live feeds and live replication immediately, return a receiver and send a notice after each commit:

```rust
// 0.5, in a custom adapter
fn subscribe(&self) -> Option<tokio::sync::broadcast::Receiver<ChangeNotice>> {
    Some(self.notices.subscribe()) // send ChangeNotice { seq, doc_id } after each commit
}
```

## Exact numbers (opt-in)

Nothing changes by default. The new `arbitrary-precision` feature keeps JSON numbers exactly as written (integers beyond `i64`/`u64`, long decimals):

```toml
rouchdb = { version = "0.5", features = ["arbitrary-precision"] }
```

It enables serde_json's `arbitrary_precision` for the whole build: `serde_json::Number` then compares textually (`1.0 != 1.00`), and revision ids of documents containing such numbers differ from those computed without the feature. See also "Differences from CouchDB" in the reference.

## Server (`rouchdb-server`)

`ServerConfig` has new fields, so add `..Default::default()` to struct literals:

```rust
use rouchdb_server::{AdminCredentials, ServerConfig};

// 0.4
let config = ServerConfig { port: 5984, host: "0.0.0.0".into(), db_name: "mydb".into() };

// 0.5
let config = ServerConfig {
    port: 5984,
    host: "0.0.0.0".into(),
    db_name: "mydb".into(),
    admin: Some(AdminCredentials::parse("admin:secret").expect("user:password")),
    cors_origins: vec!["http://localhost:3000".into()],
    ..Default::default() // max_request_size: 64 MiB, session_timeout: 10 min
};
```

**CORS is off by default.** A browser app served from another origin must be allowed explicitly; in 0.4 every origin was mirrored with credentials:

```sh
rouchdb-server mydb.redb --cors-origin http://localhost:3000   # or ROUCHDB_CORS_ORIGINS
```

**Authentication is opt-in and recommended** whenever other software can reach the port (the server warns when it listens on a non-loopback address without it):

```sh
ROUCHDB_ADMIN=admin:secret rouchdb-server mydb.redb --host 0.0.0.0
```

Everything except `/`, `/_session`, `/_uuids` and `/_utils` then needs Basic auth or a `_session` cookie. Wrong credentials are a 401 on every route, and session cookies expire after 10 minutes without use (`--session-timeout`).

HTTP clients of the server may notice:

| Request | 0.4 | 0.5 (CouchDB) |
|---|---|---|
| `DELETE /{db}` | database still served | 404 on every route until `PUT /{db}` |
| wrong-shape JSON body | 422 | 400 |
| `DELETE /{db}/{docid}` without a rev | 400 | 409 |
| design-document conflict | 201 `"ok": false` | 409 |
| `_bulk_docs` with an invalid document | 201 (written, or a per-document error) | 400, nothing written |
| `_bulk_docs` with `new_edits: false` | one result per document | failures only (`[]`) |
| `_find` without `limit` | every match | at most 25, with a bookmark |
| `POST /{db}/_index` response `id` | index name | `_design/<ddoc>` (also listed in `_all_docs` / `_changes`) |
| `_all_docs?key=b` | accepted | 400; JSON-encode keys (`?key="b"`) |
| `_changes` with an unknown feed or filter | ignored | 400 / 404 |
| `POST /{db}/_compact` without `Content-Type: application/json` | 202 | 415 |
| `/_uuids`, `POST /{db}` generated ids | hyphenated UUIDs | 32 hex digits |
| `POST /{db}/_all_docs` with `keys` | unknown keys dropped | one row per key: `{"key": …, "error": "not_found"}`, `"offset": null`, `"doc": null` for deleted docs |
| `GET /{db}/_design/{ddoc}` | typed members only | the stored document, with the usual document options and headers |
| `PUT`/`DELETE /{db}/{doc}/{att}` with a malformed `?rev` | 404/409 when the document is missing | 400 `Invalid rev format` |
| anonymous `POST`/`PUT`/`DELETE /` or `/_active_tasks` | accepted | 405 `Only GET,HEAD allowed` |
| several `AuthSession` cookies | any valid one | only the first counts |
| malformed `AuthSession` cookie | ignored | 400 on every route, even with valid Basic credentials |
| malformed JSON body | axum's message | 400 `bad_request` "invalid UTF-8 JSON" |
| request body over 2 MB | 413 | accepted up to 64 MiB (`--max-request-size`) |
| error bodies | sometimes plain text; reasons like the doc id | always JSON, CouchDB names and reasons (`missing`, `deleted`, `Document update conflict.`) |

## CLI (`rouchdb`)

- Read-only commands fail with exit 1 on a missing file instead of creating an empty one.
- `replicate` exits 1 when `ok` is `false`; its output gains `errors` and `last_seq`.
- `dump` inlines attachments (base64) and `import` restores them. `dump` still exports only winning revisions; use `replicate` to copy conflicts and history.
- `ROUCHDB_USER` / `ROUCHDB_PASSWORD` supply credentials for http(s) URLs that carry none, and errors never print `user:password@`.

## redb files

No manual step is needed, but the upgrade is one-way, and it happens as soon as a 0.5 build **opens** the file, not only when it writes:

1. **Back up the `.redb` file before you first open it with 0.5** if you may need 0.4 again. Any open runs the upgrade, including read-only commands such as `rouchdb info` or `rouchdb get`.
2. The upgrade (in `RedbAdapter::open`) re-keys attachment bytes by digest and computes document counts. After it, **0.4 may no longer read the file's attachments**.
3. Revision trees are rewritten in a flat format the next time each document is written; **0.4 cannot read those documents**. Both formats are readable by 0.5.
4. Attachments stored by 0.4 read back with `revpos` 0.
5. A file written by a newer RouchDB is refused with an error and left untouched.

```sh
cp mydb.redb mydb.redb.0.4-backup   # before the first 0.5 open
rouchdb info mydb.redb              # upgrades the file in place
```
